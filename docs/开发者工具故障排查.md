# 单元加载与资源提示

## 单词、例句为空并显示“单元加载失败”

旧版通过 `FileSystemManager.readFile` 读取分包中的 `.json` 单元文件。小程序编译器把 `.json` 用作配置，不能把源码目录中能读取到的文件当作编译后仍可原样读取的资源。本次改为原字节的 `.txt` 文件，并在 `project.config.json` 的 `packOptions.include` 明确包含 8 个单元资源目录；仍使用 `JSON.parse` 读取数据，没有修改课程内容。

加载代码同时修正失败分包的重试缓存，并分别提示分包下载失败、资源文件缺失、文件内容损坏。控制台会记录 `[course] Unit N 加载失败` 和具体路径及原始错误，避免全部被显示成网络问题。

更新方法：

1. 下载 `wechat-miniprogram` 分支最新完整压缩包，解压到新的目录。
2. 导入含 `project.config.json` 的根目录，填入自己的 AppID，并保留自己的云环境及音频配置。
3. 在开发者工具清除全部缓存，重新编译；确认 Unit 1 和 Unit 120 都各显示 15 词、15 句。
4. 若仍报错，打开“调试器 / Console”，查看第一条红色错误及 `[course]` 记录。截图上的“调试器 5”只是计数，本身无法说明五条错误的具体原因。

本次验证覆盖全量资料、原生 WXML/WXSS 编译和模拟打包文件访问限制。尚未在用户这台 Windows 开发者工具或真实手机运行，需重新编译确认实际结果。

## “图片和音频资源大小应不超过 200 K”未通过

工程目前保留 Unit 1 的演示录音，内置录音合计约 3.9 MB，因此媒体体积优化项仍会提示未通过。这项提示与单元资料读取失败应分别排查；不能仅凭代码质量面板推断具体运行报错。

各分包仍低于本工程检查的 2 MiB 预算，总代码包低于 20 MiB 预算。`audio-resources/` 和新增加的 `audio-by-unit/` 在 `miniprogramRoot` 之外，不属于上传的小程序代码包。把 Unit 目录重新整理不会增加小程序代码包。

正式音频接入自己的云存储后，可选择在线音频版本，移除演示音频分包以降低媒体体积；当前版本保留已提供的 Unit 1 离线演示能力。原始音频不是删除对象，完整录音仍用于云端部署。此优化提示不代表已部署云音频，也不能代替正式上传和真机检查。
